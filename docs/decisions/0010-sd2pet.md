# 0010: The SD2PET is a behavioural device that runs NODISKEMU's DOS

**Status:** accepted

## Context

The owner's PET uses an SD2PET Future: an ATmega1284P on the IEEE-488 bus running NODISKEMU, a
fork of sd2iec. It runs no 6502 code. Emulating it faithfully is the project's priority, against
measurements the owner made on it (`../PETTest/README.md`, §8): per-byte cycles with the
kernal's CHRIN, a stripped receiver and an inline one (152, 111, 58), whole sectors, the cost of
sending a command, CHKIN and CLRCHN.

The owner's VICE build approximates it with an emulated 4040 whose CPU runs 8 times faster and
whose controller's delay is shortened. Per byte it matches, but a whole sector with the inline
receiver comes out 12 % short: the command is accepted about twice too fast and the block read
takes about twice too long, partly cancelling. A model with one clock cannot set the two apart.

TangPet emulates the drive with a hardware handshake and a DOS of its own, written for it. It
differs from NODISKEMU in what PET programs see: writing outside an image, many commands
(`N`, `C`, `P`, `M-R`, `MD`, `RD`, `X`), `CD` paths, listings and their filters, wildcards,
images, channel count, and the `#` buffer's first byte.

## Decision

- **The device is behavioural.** No drive CPU is emulated. A state machine drives the bus lines
  as the SD2PET's firmware does: as listener and as talker, under ATN, with EOI.
- **Its timing has a parameter per phase** the owner measured, each set from the measurements:
  the response to ATN and to each byte as talker and as listener, the time to take a command
  character, to execute a command, to find a sector, and to cross a sector boundary of a
  sequential file. The bench programs that made the measurements run in the emulator as tests,
  and their counts are held to the hardware's.
- **Its DOS is NODISKEMU's**, ported to C++ ([0004](0004-licence-gpl-2.md)): its command
  parser, its error channel, its directory listings and filters, its image formats (D64, D80,
  D82, D81, D71, DNP), and its file operations on the card. A host directory stands for the SD
  card; the FAT layer is replaced by the host's file system. Fast loaders, drive memory writes
  for them, the clock and the EEPROM are left out.
- The NODISKEMU commit ported is the one whose version the owner's SD2PET reports, once known
  ([open question](../open-questions.md)); until then, upstream's head at the time of the port.

## Consequences

- A disagreement with the owner's measurements is fixed by a parameter or by the state machine,
  not by a clock that moves everything at once.
- What the real SD2PET does that the measurements do not cover (the OPEN of a named file, the
  interleaving of a `#` buffer with a file) is modelled from NODISKEMU's code until the owner's
  `openbench` and `switch` programs are measured.
- TangPet's DOS tests are a secondary check only, where its behaviour and NODISKEMU's agree.
